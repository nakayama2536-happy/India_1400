# 参照データ時刻の予定更新表示 — UI v5.36

## 目的と変更範囲

2026-10-20 の依頼（#68）。14:04 に生成した休場日の保存データが、17時台には単に数時間経過したことだけで赤くなるため、参照時刻カードを更新予定と判断時間で表示する。

- 緑：営業日の 14:00 <= JST < 15:00、同日の更新枠を取得済みで、その項目の取得・日時・基準を確認できた場合。
- 黄：時間外・休場・参考値・明示された正当な取得省略。営業日不明、当日更新前、参考扱いの項目を緑にはしない。
- 赤を優先：予定更新の未反映、取得失敗・キャッシュ代替、必須欠損、不正・未来日時、保存時点の STALE / UNAVAILABLE、日足・NAV 基準不整合。時間外への切替で異常を隠さない。

変更対象は判断タブと品質タブの参照時刻カードおよび説明文。`referenceHealth`、`runtimeSnapshotFreshness`、`decisionDisplayEligible`、売買条件、購入記録の読み書き、大文字の実行状態表示は変更しない。参照カードの緑は予定更新と項目確認の表示であり、現在の売買可否は別の既存ゲートで判断する。

## 更新枠と表示上の猶予

JST。曜日は休日カレンダーではなく実際のワークフローの月〜金スケジュールに合わせる。インドの平日休場でも更新処理は予定されている。時刻はワークフロー完了の保証ではなく、画面が未反映を知らせ始める設定。

| 対象 | 実行予定 | 赤の開始 | 成功確認に使う時刻 |
| --- | --- | --- | --- |
| 市場・14時枠 | 13:57 / 14:03 / 14:08 | 14:25 | 同日13:45以降の `market.generated_at_jst` |
| 市場・引け後 | 19:47 | 20:10 | 同日19:47以降の `market.generated_at_jst` |
| ファンド | 19:15 / 20:15 / 22:20 / 23:45 | 各予定の15分後 | 対応予定以降の `india_core.fetched_at_jst` |

14時枠は Core の取得窓13:45〜14:20と3回の試行を一つの枠として扱う。14:04の成功後に14:08の再試行がないだけでは赤にしない。14:25は最終試行から17分、20:10は引け後試行から23分の猶予。Core jobのtimeoutは15分。ファンドjobのtimeoutは8分。

更新枠の確認は生成・取得時刻からの表示判定。ブラウザーからActions実行ログを取得しないため、赤は「予定更新が未反映」であり「ジョブ失敗」と断定しない。再読込・実行履歴の確認へ案内する。手動更新も対応枠以降の正常な保存データであれば反映確認として扱う。これは14:00履歴を遡及生成・認定する処理ではない。

週末は最後の平日の期限を引き継ぐ。金曜の更新失敗は日曜も赤、正常な金曜夕方のデータは日曜も参考表示。月曜の新しい期限までは土日を理由に失敗扱いしない。前日までの期限未達は当日の猶予で隠さない。ファンド最終枠は翌日00:00に期限を迎える。

実装確認元：Core `.github/workflows/update-market.yml` / `v59_acquisition_status.py`（main `e4bd788cd0dd8e9611eed833ee83e07fe130fc41`）と Public `.github/workflows/update-india-core.yml`。スケジュール変更時は `referenceUpdateSchedule` とテスト・この説明を同時に変更する。

## 各項目の扱い

24時間は取得時点で既に古くなっていないか、判断時間内で24時間を超えていないかの補助条件。24時間以内でも予定更新未反映や取得異常は赤。土日に経過時間だけで正常な前回更新を赤にしない。

- 確定日足：保存された確定基準日、日足取得状態、連続性の異常を確認。新しい休日カレンダーをUIに複製しない。
- NAV：公式取得と計算基準日の整合、および独立した取得予定を確認。市場データの生成時刻でNAV取得成功を代用しない。
- NIFTY / VIX：休場・確定セッションの保存値は基準日と照合して黄。前日の休場情報だけで今日を休場とは認定しない。
- INR/JPY：両方の為替取得状態を確認。現在レートが存在しても欠けた5日変化率を補完しない。
- FII/DII・騰落数：任意の公表参考値は黄。休場省略は同日の明示的CLOSED証拠が必要。取得失敗を省略扱いにしない。
- 時刻：タイムゾーン付きISO日時のみ受理。不正日付、未来日時、時刻だけがある価格欠損を赤にする。
