# UI 5.34: 保存時点と現在の判断を区別

## 目的・最小変更
- 必要性：休場・経過時間・追加分析非該当を「正常」と読み違えないようにする。
- 現状不足：14:04生成データの閲覧時点で鮮度警告が出る一方、追加分析欄がOFF/正常と表示される。次のアクションが祝日名だけになっている。
- 最小安全：表示だけを修正。既存鮮度閾値、売買ゲート、保存JSON、端末購入記録は変更しない。取得失敗・未来時刻・保存時STALEの警告を維持する。

## 変更
- 当日・過去時刻・CLOSED・非営業日の証拠がそろう場合に限り、休場対象外の見出しを表示。
- 次のアクションに次回営業日の14時更新確認と対象外理由を表示。
- 経過時間の警告は現在判断用であること、生成記録は保持されることを明記。
- 追加分析OFFを「非該当（保存時点）」に変更。現在判断できない場合のトリガーなしは黄色の参考表示とする。重大トリガーは維持。
- 予測基準日と生成時刻、保存条件集計であることを明示。
- 指標の「適切」を「データ確認済み」に変更。
- 3分割の段階名重複を除去し、条件充足数を文章化。
- 為替寄与未算出時は不足するFXレッグ・派生変化・株式騰落率を区別。

2026-10-20 14:04:36 JST生成の公開JSONではUSD/JPY・USD/INRの現在価格があり、両方のchange_5d_pctはnull、取得元はGoogle Finance。
Private coreの取得経路を確認したところ、採用された現在レート取得経路は5日変化を返さない。円換算寄与は両通貨の5日変化を必要とするため未算出となる。
観測履歴は正式な終値や同期した5営業日変化の証拠ではない。欠損を0や異なる比較期間の値で補完しない。5日変化そのものを供給する機能は今回のUI修正では追加しない。

## 17:08実機画像に基づく追加修正
- 成功後の経過時間は「鮮度期限超過」、保存時点のSTALEは「保存時点で鮮度不足」と表示。取得失敗・今回未取得・時刻不明・未来時刻は従来どおり別表示とする。
- 為替・原油・生成時刻の鮮度閾値と赤色は維持。休場を理由に鮮度を免除しない。
- 次回営業日待ちを案内する前に、当日の非未来生成時刻、CLOSED、非営業日の証拠を確認する。矛盾や古い休場情報では確認を促し、待機だけを勧めない。
- 次回営業日の具体的な日付は推測しない。祝日名と14:00更新後の確認行動を表示する。
- 追加後の検証：Node全92件、Python全70件、公開データ検査に合格。ブラウザ本体が未導入のため、新表示のブラウザ描画・iPhone実機確認は未実施。CIは更新後のコミットで別途確認する。
