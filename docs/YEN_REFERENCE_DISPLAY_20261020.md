# 為替の影響（参考）の表示統一 — UI v5.37

## 目的

#70。v5.36で参照データ時刻を予定更新・判断時間による表示へ変更した一方、円換算欄には以前の20/30分鮮度判定が残っていた。ユーザーが提示した2026-10-20 17:59の画面では、休場日の正常な保存レートと履歴不足がすべて赤に見えていた。

## 表示

- 見出しを「為替の影響（参考）」へ変更。インド・コアの基準価額は既に円建てであり、二重に円換算する欄ではないことを説明する。
- 1ルピー（INR）を先頭に置く。USD/JPY・USD/INRも「1ドル」と単位を示し、3つすべてに参照日時を付ける。
- レートは `referencePresentation` を共用。緑＝判断時間内で更新確認済み、黄＝休場・時間外・参考、赤＝予定更新未反映・取得異常等。参照データ時刻と判定を重複実装しない。
- 為替寄与は、元の比較履歴不足なら黄の「未算出（履歴不足）」と `--`。不正数値・計算結果の欠損・利用可否の矛盾は赤。取得異常や予定更新未反映は履歴不足より優先し、赤の理由を表示する。
- 計算済みの影響は `+/-数値pt` と「円換算にプラス／マイナス／中立」で表示する。枠と状態色はデータの確認状況に従い、数値の符号で枠色を変えない。値の文字色は白で固定する。
- 未算出を0に変換しない。実際の計算値0は0.00ptで中立と表示する。欠けた履歴を作らず、再取得すれば必ず次回に計算できるとは約束しない。
- 毎分の `renderClockDependent` に同欄を追加し、15:00や予定更新の期限をまたいだ時に参照カードと同時に再判定する。

## 変更しないもの

データ取得、為替寄与の計算式、保存JSON、売買条件、`referenceHealth` と判断ゲート、端末内購入記録、大文字の実行状態表示。履歴取得の改善はこの変更には含まれない。

## 検証

関連Nodeテスト66件成功（新規11件を含む）。休場日の実例、レート単位と日時、共通参照表示との一致、毎分の15:00/20:10遷移、取得失敗と履歴不足の優先順位、正負とゼロ、不正値・欠損・矛盾、外部文字列のHTMLエスケープを検証した。既存の売買ゲート・購入記録テストも成功。
